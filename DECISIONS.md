# Decisions

- `npm test` uses `node --test "test/*.test.js"` because Node 24 no longer accepts a bare directory argument.
- Phase 1 shared-module tests live in one file, `test/shared.test.js`, instead of one file per module.
- `src/shared/` also exports `mergeConfig`, `findCollisions`, `stripMarkdown`, `openInMaps`, `shortlistCount` and `allVisible` as small helpers for later phases.
- `renderMarkdown` turns headings into bold paragraphs and drops images and unsafe link schemes, keeping the subset small.
- The embedded `#trip-data` JSON also carries each stop's `minutes` (not a date) so `trip.js` can recompute totals when the low-rating toggle changes.
- A leg connector is shown only when the stop and the next stop in the original order are both visible, so a hidden stop never leaves a wrong leg between two visible ones.
- `buildSite()` is exported from `build-site.mjs` so tests call it directly; the CLI runs only when the file is the entry point.
- Google Maps bootstrap loader lives in `src/shared/maps-loader.js` so the site and the editor share it.
- Trip records carry an extra `auto_sync` flag, set after the first Sync press, so automatic retries only touch trips the user has synced before.
- `github.js` treats a 422 whose message mentions `sha` or `does not match`, and any 409, as a conflict.
- The `getFile` helper returns `{ data, sha }` (or `null` on 404) and `putFile` returns the new sha; `ConflictError` is raised for sha mismatches.
- The service worker only skips waiting when the page posts `skip-waiting` (the "Update available" toast), so a running session is never swapped under the user.
- No automated render smoke test for the editor (it needs a DOM and the spec forbids new dependencies); the editor was exercised by hand in a browser against a seeded IndexedDB trip (expand, rate, drag across sections, undo, toggle) with no page errors.
- Dragging uses `newDraggableIndex` and puts the dragged node back with `item.remove()` before `insertBefore` so same-list moves revert correctly.
- Editor "Add stop" navigates to the Capture screen in search mode (`#/capture/<tripId>~<sectionId>`), implemented in Phase 5.
- Editor screens render only after local data has loaded (`ready` signal), so opening the app straight on `#/capture` never mistakes an empty store for "no trips".
- Capture: choosing "New trip…" creates a log titled "<city> trip" from the first selected place (or "New trip") and makes it the active trip.
- Workflow action majors (`checkout@v5`, `setup-node@v5`, `configure-pages@v5`, `upload-pages-artifact@v4`, `deploy-pages@v4`) all exist, so they are used as listed.
- `create-data-repo.sh` checks the `workflow` scope through the `X-OAuth-Scopes` header; tokens that do not report scopes (such as fine-grained ones) are asked to run `gh auth refresh -s workflow`.
